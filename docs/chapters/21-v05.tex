\chapter{Version 0.5: Large-scale domain applications}
\label{ch:v05}

Version 0.5 puts \algolang{} to work on ten demanding domains, one enterprise application each. Every application runs real, deterministic algorithms over large synthetic datasets as company tools. The \algolang{} program around them adds what the algorithms alone do not have: parallel agents, deterministic guards, human gates, four-eyes approvals, risk levels, evals, behaviour tests and system cards. Each tool reports its own accuracy, validation or back-test, so a flow never acts on an unchecked number.

\section{The pattern every application follows}

\begin{algo}[title=enterprise-apps/smart-city-operations/programs/city\_operations.algo (flow)]
flow main(situation: text) {
    [air, waste, power] = par { AirQuality(situation), WasteRoutes(situation), PowerForecast(situation) }
    if air contains "AQI SEVERE" or air contains "AQI VERY POOR" {
        emit air, waste, power, HealthAdvisory(situation, air)   // the duty officer approves
    } else {
        emit air, waste, power, DailyBrief(situation, air, waste, power)
    }
}
\end{algo}

\begin{itemize}
\item Company tools compute; agents explain and decide. A guard such as \code{contains "AQI SEVERE"} is deterministic: it reads the tool's verdict, which is written first on its first line.
\item Tools validate themselves: cross-validation, held-out genes with a negative control, back-tests, agreement with recorded conditions.
\item Public actions (health advisories, load shedding, wet-lab plans, fleet hire) go to people; money and safety decisions need two approvals.
\end{itemize}

Version 0.5 also adds \code{algo run FILE --flow NAME} to run any flow of a program, and makes the offline model's robustness tests independent of the wording of a goal.
